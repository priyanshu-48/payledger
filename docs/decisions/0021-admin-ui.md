# ADR 0021: Admin console (React) and the read endpoints behind it
- Status: accepted · Date: 2026-10-26
## Context
SPEC M9: an admin UI for accounts, payments with their status history, reconciliation runs and dead-letter replay, proven by a Playwright smoke test. The backend only had by-id reads, and the three services run on three origins with no CORS.
## Decision
- **Same origin through nginx.** The UI image builds with Node and serves with nginx, which forwards `/api/auth/`, `/api/payments/` and `/api/ledger/` to the services (prefix stripped). Vite's dev server has the same table. No CORS configuration is added to any service, and the same image works on any host. nginx answers 404 for the mock bank and for every `/actuator` path, so the browser cannot reach them, and adds `nosniff`, frame denial, no referrer and a `default-src 'self'` content security policy.
- **Token in memory only.** The access token lives in a module variable; a page reload signs out. It is never in `localStorage`, cookies or the URL, so script injection cannot lift a stored token. The cost is signing in again after a refresh, acceptable for an operator tool. The role shown in the UI (read from the token) only hides menu entries; every decision is made by the services, and their 403s are shown as they are.
- **Three read endpoints added** (the only backend change), paged with a capped size: `GET /accounts` (ADMIN; owner and type filters; balance joined from `account_balances`), `GET /payments` (ADMIN sees all, a MERCHANT only its own through `PaymentAccess.merchantScope`, others 403; status filter), `GET /recon/runs` (ADMIN; latest 50). All newest first. Existing endpoints are unchanged.
- **Small on purpose:** React, TypeScript (strict), Vite and react-router, plain CSS, one fetch wrapper. No component library or state library. Amounts are shown from the API's decimals and never calculated on in the browser.
- **Testing:** Java tests for each new endpoint (roles, filters, ordering, size cap) and one Playwright test against the real compose stack (`ops/ui/smoke.sh`): wrong password, admin works through all four areas including freeze, capture and a reconciliation upload, a merchant sees only its own payments, a reload signs out. It drives the installed Microsoft Edge, so nothing is downloaded. CI builds and type-checks the UI; the Playwright run needs the whole stack and stays in the script (a Jenkins stage later).
## Consequences
A reload means signing in again. nginx must be able to resolve the three service names at start-up (compose `depends_on`). Pagination is previous/next only; account search is by exact owner. The login rate limit (10 a minute per address, ADR 0019) applies to the UI like any client.
## Alternatives rejected
CORS on every service (three configurations to keep in step, and the browser would talk to internal ports); an API gateway service (another component for a proxy table); a token in `localStorage` or an httpOnly cookie (the first is readable by script, the second needs CSRF protection and a session endpoint in auth-service); a UI library such as MUI (large for six screens).
